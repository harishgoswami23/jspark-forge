# JSPARK Forge v0.6.0

*Token care: see where the usage goes, and hit limits less often.*

Released 2026-11-21.

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already installed: it updates by itself when Claude Code starts. Needs Node.js 18 or newer.

## What was measured first

On a real two-day session (2026-11-21):

- Almost all usage was the conversation being re-read. Every step re-reads the whole conversation so far, and it had
  grown to about 417k tokens per step on average, over 500 steps.
- Helpers were second: 15 builders ran 790 steps at about 132k tokens re-read per step.
- JSPARK Forge's own notes to Claude were about 8k tokens in all. Trimming them would save almost nothing, so that was
  not done.

## New

- **`/jspark-forge:usage`.** Where this session's tokens went, in plain words: steps and tokens re-read per step for
  the main conversation and for each kind of helper, the biggest tool outputs, what JSPARK Forge itself added, and what
  would save most. It reads only the session's own record inside the Claude folder and changes nothing.
- **A note when the conversation gets long.** At the end of a reply, each time the conversation passes another 150k
  tokens, JSPARK Forge tells you that a new session would save usage. The note goes to you, not to Claude, so it costs
  no tokens. The handoff is saved on every message, so a new session and "resume" loses nothing.
  `- fresh-session: off` under `## Settings` in `rules.md` stops it.
- **Helper habits.** Every helper is told four habits when it starts: run only the tests of what it changed while
  working, and the whole suite once at the end; send long output to a file and read only the totals and the failing
  lines; read the needed part of a file, not a large file whole; report in short bullets. The main session is told to
  give each helper one task and to let the checker helper run long test suites. The builder and checker helpers follow
  the same habits. `- usage-care: off` stops both texts (the two helper files keep the habit).

## Limits

- Token counts are the ones Claude Code records for each step. Sizes of tool outputs and of JSPARK Forge's notes are
  estimates (about 4 characters per token).
- The helper habits are instructions. JSPARK Forge cannot make a helper follow them; `/jspark-forge:usage` shows the
  steps per helper, so you can see whether they help.
- The "new session" note needs the session's record inside the Claude folder; without it there is no note.
- How a plan's limit weighs re-read tokens is not published. The report says how many there were, not what they cost.
