# JSPARK Forge v0.6.2

*Six small fixes from real use in another project.*

Not released yet.

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already installed: it updates by itself when Claude Code starts. Needs Node.js 18 or newer.

## Where this came from

A Claude session that used JSPARK Forge in another project was asked to rate it. It said 7 out of 10 and named six
things that cost time or tokens. This release fixes those six. The larger ideas from the same feedback (better build
graph checks) are not in it.

## Changed

- **No second "Continue?".** At a session start JSPARK Forge shows you one line and says "Say 'continue' or tell me
  what to do instead". If your first message is "continue", "resume", "go on" or "yes", that is now your answer:
  Claude says where the work stands in at most 4 lines and carries on. Before, it asked "Continue?" again and waited.
  If your first message is a question or a new task, nothing changes. A crash check still comes first.
- **A shorter handoff.** "Files touched in this task" shows the newest 8 and a count ("+42 more"). Before, a long
  task listed up to 50 file names at every session start. The rest is in the log, which the handoff names.
- **Honest gate status.** A build graph check that was handed out, and that nobody is running, is now shown as
  "not yet passed (1 of 2 commands passed, none running)". Before, it said "running". "Running" is said only while
  `graph gate` is running the commands.
- **No more "Gate gate".** Messages about a check read "Step <id> (gate) passed", "… failed", "… still needs".
  A step that is itself named `gate` reads correctly.
- **Notes carry their date.** Claude's notes in the handoff show the date when they are not from today, and the
  label says: re-check any caution or limit before acting on it. The reminder to update the notes also asks Claude to
  write what was measured behind a caution (for example "free memory was 2 GB") and to drop one that no longer holds.
- **Who decides what, with superpowers.** When superpowers is installed too, one line at session start says:
  superpowers sets the method, JSPARK Forge sets the guard rails; if the two still disagree, your own instruction
  comes first, then the block list and grounding rule, then superpowers.

## If you have scripts that read JSPARK Forge's output

Two texts changed: "Gate <id> …" is now "Step <id> (gate) …", and a waiting gate's state is shown as
"not yet passed (…)" instead of "running". The record file itself (`.jspark-forge/state/graph-<name>.json`) is
unchanged.

## Still open

- The demo GIF in the README is a placeholder.
- The code map does no per-file refresh of its own and uses no git post-commit hook; read-only sources record no
  "last read". All three are written in the spec as deviations.
- The "no second Continue?" fix and the "who decides what" line are instructions to Claude, not hooks: they are
  tested as text, and a real session start has to show they work.
- One macOS check (Node 18) hung once on the v0.6.1 pull request and passed when run again. The cause is not found.
