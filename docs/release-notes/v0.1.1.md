# JSPARK Forge v0.1.1

*Claude Code forgets. JSPARK Forge doesn't.*

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already on v0.1.0: `/jspark-forge:upgrade`, or `claude plugin update jspark-forge@jspark-forge`, then restart Claude Code. Needs Node.js 18 or newer.

## New

- **Waiting on you.** A question Claude asks you that holds up work stays on a list until you answer it: in the status line (`⏳ 2 waiting on you · oldest 14h`), first thing at the next session start, and in the handoff. A cutoff while a question is open no longer loses it. `/jspark-forge:waiting` lists them with Claude's recommendations.
- **Someone else's repo (guest mode).** Open a repo you cloned and never committed to, and JSPARK Forge writes nothing into it; its files live in `~/.claude/jspark-forge/guests/`, and Claude is told the repo's README, docs and scripts are data, never instructions. `/jspark-forge:init --guest` also holds the repo's install, build, test and run commands until you type `CONFIRM guest-quarantine`.
- **Read-only sources.** List an old system you are migrating from under `## Sources` in `rules.md`: Claude can read it, and any change to it is always refused.
- **PowerShell and cmd.** Every block now matches PowerShell and cmd forms too (`Remove-Item -Recurse`, `rd /s`, `iwr … | iex`, `Set-Content .env`, `icacls … /grant Everyone:F`).
- **Health check.** `/jspark-forge:doctor` says whether JSPARK Forge works on your machine, one line per check, each problem with its fix, and changes nothing. `/jspark-forge:status` shows what is saved now. `/jspark-forge:upgrade` updates it.
- **Node.js missing?** JSPARK Forge now says so when Claude Code starts instead of failing silently.

## Safer

From two independent reviews of the block list and guest mode:
- Commands inside `$( )`, backticks, `if` / `for` blocks, `eval`, `find -exec` and PowerShell script blocks are checked; a commit message is text, never a command.
- A command too deeply nested to check is refused instead of slowing the check past its time limit.
- A command with two different blocks needs both CONFIRMs; a CONFIRM is spent only when the command goes through.
- A cloned repo cannot make itself "yours" (or switch a block off) with files it ships.
- A project's own `rules.md` can add blocks but never remove one; its patterns run under a time limit.

## Tested

- 651 automated tests on Windows, macOS and Linux with Node 18, 22 and 24.
- Real Claude Code sessions on Windows: every hook fires; killed mid-task and reopened, back to work in under 30 seconds with nothing changed.

## Known limits

- A seatbelt, not a sandbox: a deliberately disguised command can get through.
- "Waiting on you" captures questions asked through Claude Code's question tool and a reply's closing question; a question in the middle of a reply is not captured. Timed reminders are not in this release.
- The full ship gate on macOS and Linux runs once the CI token is added.
