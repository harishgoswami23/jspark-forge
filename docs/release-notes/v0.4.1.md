# JSPARK Forge v0.4.1

*Claude Code forgets. JSPARK Forge doesn't, including where things were in the old system.*

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already installed: `/jspark-forge:upgrade`, then restart Claude Code. Needs Node.js 18 or newer.

## New

- **Code map of the old system.** If you are migrating and list the old system as a readonly source (`## Sources` in
  `.jspark-forge/rules.md`), Claude can index it with codebase-memory-mcp as its own map and answer "where is X in the
  old code?". Every such answer is labelled **old code**, with the old system's commit, and reminds Claude never to
  edit it. If the old code changed since it was indexed, the answer says so and gives the one call that re-indexes it.
  Your readonly sources are listed when a session starts, in `forge.js map status` and in `/jspark-forge:check`.
  This was planned for v0.3 and missed; a review of the plan against the releases found it.

## Tested

- 1,512 automated tests on Windows, macOS and Linux with Node 18, 22 and 24.

## Known limits

- Needs codebase-memory-mcp, like the rest of the code map.
- The old system's freshness is checked through its own git commit; for a folder that is not a git repo, the answer
  gives the time it was indexed and says changes cannot be detected.
