# JSPARK Forge v0.2.0

*Claude Code forgets. JSPARK Forge doesn't, and now it remembers why.*

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already installed: `/jspark-forge:upgrade`, then restart Claude Code. Needs Node.js 18 or newer.

## New

- **Decision memory: the "why".** One-line decisions, rules and lessons, each with the files it touches, kept in `.jspark-forge/decisions.md` (committed with your code). Just before Claude changes one of those files, it is shown the decisions about it, as project notes it must not contradict without asking you. After a commit that settled a real choice, or a plan you approved in plan mode, Claude offers *"Record the decision?"* with a one-line draft; nothing is recorded until you say yes, and every recording is announced. `/jspark-forge:decisions`, `/jspark-forge:decide`, `/jspark-forge:check` ("is my memory still true?").
- **Database guard.** A write to a production database (through a database MCP server or `psql`, `mysql`, `sqlcmd`, `mongosh`, `supabase db`, `prisma migrate deploy` and others) waits for `CONFIRM db-write`. Reads are never blocked. Mark a dev database in your own `~/.claude/jspark-forge/rules.md`.
- **Which model does what.** Four helpers on the model strength their job needs: `planner` and `reviewer` on the strongest model, `builder` on a standard one, `checker` on a light one; reviewer and checker cannot edit.
- **Skill and brief templates** with a checker (`/jspark-forge:new-skill`, `/jspark-forge:new-brief`, `forge.js lint`), and `JSPARK-FORGE.md`: the same rules as one file for tools without plugins.
- **Licence check** for repos you review and old systems you migrate from: one plain line, once (a hint, not legal advice).
- **UI work:** in a project with a front end, a one-time tip naming the companions that make UI work first-class: Anthropic's frontend-design skill, Playwright MCP (Claude checks its own screens) and shadcn/ui.

## Hardened before release

An independent code review (Fable 5.2) found four serious gaps; all are fixed and covered by tests:
- the database guard now holds anything that is not a read (and a host it cannot resolve counts as production);
- a crafted file pattern can no longer slow a hook down;
- text that arrives with a repo is always cleaned and length-limited before Claude sees it;
- the licence check names full GPL texts correctly.

Also fixed, found while reviewing a later release (these gaps were in v0.1.1 too):
- `cmd //c "…"` from Git Bash, and `winpty`, no longer get past the block list;
- a command split over lines with a backslash is read the way bash joins it, so a dangerous command cannot hide in
  the split;
- a database tool input nested thousands of levels deep is held, not passed.

## Tested

- 1,046 automated tests on Windows, macOS and Linux with Node 18, 22 and 24.
- Real Claude Code sessions: a decision about a file is kept when Claude changes that file (3 of 3 runs); the checker helper is dispatched and runs.

## Known limits

- Decisions reach Claude with the edit already requested: a first edit that contradicts one can land; Claude is told to stop and ask.
- With superpowers, the model map is guidance, not a lock: superpowers chooses a model for each helper it starts.
- A seatbelt, not a sandbox: a database write hidden inside a stored procedure or your application's own code gets through.
