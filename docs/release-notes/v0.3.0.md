# JSPARK Forge v0.3.0

*Claude Code forgets. JSPARK Forge doesn't: where you were, why it was built that way, and now what is where.*

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already installed: `/jspark-forge:upgrade`, then restart Claude Code. Needs Node.js 18 or newer.

## New

- **Code map, tied to your commits.** With [codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp) installed (JSPARK Forge names it once and installs nothing itself), Claude answers "where is X" and "what breaks if I change this" from a map instead of re-reading files. JSPARK Forge adds what the engine lacks: every map answer says how fresh it is ("as of 3f2e1d0", or which files changed since), the map catches up in the background after each commit, and the decisions about the files in an answer come with it.
- **Your database layout from migration files** (`/jspark-forge:schema`): tables, columns, keys and foreign keys read from your SQL migrations, each with the file and line it came from, as of your current commit. Never the live database.
- **Launch-scope guard** (`/jspark-forge:launch`, `/jspark-forge:scope`): keep a short launch list; when a new idea comes up mid-work, see its cost first (how many items, which critical paths it touches, a time range once you have finished ten items), then choose now, after launch, smaller or drop.

## Hardened before release

An independent code review (Fable 5.2) found four serious problems; all are fixed and covered by tests:
- a leftover lock can no longer block the map's background refresh, and taking over a stale lock never stops another program;
- a huge single line in a map answer or the launch list can no longer slow a hook down;
- the map never claims to be current when git could not tell;
- the SQL reader no longer loses tables in MySQL, T-SQL or with down migrations, and its output is cleaned and labelled as data.

## Tested

- 1,130 automated tests on Windows, macOS and Linux with Node 18, 22 and 24.
- Real Claude Code with the real engine on Windows: a "who calls X" answer comes with how fresh the map is; the engine's own watcher picks up edits within seconds (spike F); a background refresh outlives the hook and Claude Code itself (spike G).

## Known limits

- The code map needs codebase-memory-mcp; without it the map features stay quiet and everything else works.
- The SQL reader understands common DDL; statements it cannot read mark their table "uncertain" instead of guessing.
- The scope nudge listens for common phrasings ("let's also add…"); new scope said in other words is not noticed.
