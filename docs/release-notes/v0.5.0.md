# JSPARK Forge v0.5.0

*Claude Code forgets. JSPARK Forge doesn't, even after a crash, and now it sets itself up.*

Not released yet.

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already installed: update, then restart Claude Code. Needs Node.js 18 or newer. v0.5 was tested on Claude Code 2.1.329;
on an older Claude Code, the doctor says so when the code map engine does not start.

## New

- **Resume that survives a crash.** Every message from you saves the handoff. Tool work with no file writes (commands,
  helpers, a new branch) saves once a minute. The next session is also given what the action log holds after the last
  save. The handoff's history now comes from the log for all sessions, so resuming no longer wipes it.
- **A better handoff.** Task is your last real request, not "go on" and not a helper's report. The four requests before
  it and the end of Claude's last reply are kept. Work in another git project is named ("Also worked in"). Claude is
  asked for its notes after 12 tool calls, and notes newer than a plan file say what the task is now. Step progress is
  read from the newer task tools (TaskCreate and TaskUpdate), which current Claude Code uses in place of TodoWrite.
- **Installs once, runs on its own** (issue #7). After the one install command, JSPARK Forge sets up the rest on first
  start (list below). The code map and Playwright ship as plugin servers started through a small launcher with `npx`;
  they download on first start, never inside a hook. Playwright serves tools only in projects with a front end. The
  shadcn MCP stays a manual, per-project step.
- **The doctor reports the new pieces.** It checks auto-update, the code map, Playwright and the two companions, each
  ok or FIX with the fix.

## Fixed

- A helper's report or a system notice never counts as your message, and can never grant a `CONFIRM`. In v0.4.2 it
  could.
- Resuming a session no longer wipes the handoff's history.

## What JSPARK Forge now adds to your machine, and how to undo each

- **Auto-update**: one key in `settings.json` (`extraKnownMarketplaces`), once per machine. Undo: `/plugin`, then
  **Marketplaces**, then **jspark-forge**.
- **The code map**: `codebase-memory-mcp@0.12.1`, run through `npx` as a plugin server. Undo: `- code-map: off` under
  `## Settings` in `rules.md`, or `JSPARK_FORGE_CODE_MAP=off`.
- **Playwright**: `@playwright/mcp@0.0.86`, run through `npx` as a plugin server. Undo: `- playwright: off` under
  `## Settings` in `rules.md`, or `JSPARK_FORGE_PLAYWRIGHT=off`.
- **frontend-design and Chrome DevTools**: added once, in the background, with `claude plugin install`. Undo:
  `/plugin uninstall frontend-design@claude-plugins-official` and
  `/plugin uninstall chrome-devtools-mcp@claude-plugins-official`. Uninstalling JSPARK Forge leaves them installed.
- **Stop the automatic switch-on** of auto-update and the two companions: `JSPARK_FORGE_AUTO_SETUP=off`.

JSPARK Forge goes online only through `npx` (the first start of the two servers) and through `claude plugin install`
(once). On Windows, Defender has been seen to flag the code map engine's program wrongly (a false positive): allow it,
or switch the code map off.

Closes #7.

## Tested

- 1,592 automated tests (1,589 pass, 3 skipped) on Windows with Node >= 18; macOS and Linux with Node 18, 22 and 24: see CI.

## Known limits

- No minimum Claude Code version is checked. If the code map engine does not start, the doctor says so and tells you to
  update Claude Code.
- The shadcn MCP is not added for you.
