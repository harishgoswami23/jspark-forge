# JSPARK Forge v0.4.0

*Claude Code forgets. JSPARK Forge doesn't, now for builds that take days.*

**Install** (superpowers comes with it; no setup step):

```
/plugin install jspark-forge --marketplace harishgoswami23/jspark-forge
```

Already installed: `/jspark-forge:upgrade`, then restart Claude Code. Needs Node.js 18 or newer.

## New

- **Build graphs** (`/jspark-forge:build`). Write a long build once as steps in `.jspark-forge/graphs/<name>.md`: which
  helper does each step, what it hands to the next, which run side by side, which checks must pass, and where you act.
  Claude runs it step by step; JSPARK Forge keeps the record, so a crash, a usage limit or a new session picks up at the
  running step. Four templates to start from: software, documents, spike and ui. Graphs stay local to your machine.
  - Checked: the graph is valid and fixed for the run; outputs are the declared ones and real (a path exists, a commit
    resolves); a step that needs you completes only on your own typed `DONE <step>`.
  - Backed by evidence: the right helper ran; a check passed on its command's real exit code.
  - Guarded: Claude is blocked from editing the run's record or imitating your `DONE` / `TRUST GRAPH`; a command that
    only looks like it might asks you first. Removing a step that needs you, or a check, needs your `TRUST GRAPH` again.
  - A graph whose checks run commands needs your `TRUST GRAPH <name>` first, and again when they change.
- **A checked path for UI work.** In a project with a front end, JSPARK Forge names the companions that make UI work
  first-class (frontend-design, Playwright MCP, Chrome DevTools MCP, shadcn/ui). The new **brand-skill template** holds
  a product's tokens, colours, type, spacing, components, accessibility rules, screen states and the generic "AI look"
  to avoid. The **`ui` build graph** runs design direction → your approval of the look → build → three checks that must
  pass (screens match the approved look; no accessibility violations axe can find, phone and desktop, light and dark;
  Lighthouse scores) → design review → your final approval. Check files are ready to copy from `templates/ui/`.
- **Every git call JSPARK Forge makes no longer takes git's index lock**, so your own `git add` never fails because a
  background refresh was running.

## Hardened before release

An independent code review (Fable 5.2) tried to cheat the build graph. Every route it found is closed: running
JSPARK Forge's own hooks from the shell, editing the graph mid-run, writing the record through unusual paths, and passing a
check with a command run in the background or elsewhere. A second review of those fixes found that a network path in
a command could stall the safety check past Claude Code's time limit, so no block applied; and that everyday commands
were refused. Both are fixed: lookups never wait on network paths, and a command JSPARK Forge is only guessing about
now asks you instead of refusing. A third review aimed only at the safety check found one more stall (a file pattern
with many wildcards) and a few quieter routes to the record; all are fixed, and 2,687 hostile command combinations
now get an answer well inside the time limit. The README now states honestly which protections are
enforced, which rest on evidence, and which are guarded: none of this is a sandbox against a program written to a file
and run on purpose.

## Tested

- 1,505 automated tests on Windows, macOS and Linux with Node 18, 22 and 24.
- Real Claude Code on Windows: a small build graph runs end to end (a helper step, then a check judged by its exit
  code), alongside the earlier resume, hook, decision and code-map tests.

## Known limits

- Human steps (`DONE`) and `TRUST GRAPH` need an interactive session.
- The order of steps and the limit on helpers running at once are handed out, not enforced: Claude could do other work.
- A failed check can be run again without limit; each result is recorded, and the step passes only on a real pass.
- A template copied for a new graph needs its title changed to `# Graph: <name>` (`/jspark-forge:build` does this).
- The UI checks need Playwright, axe and Lighthouse installed in your project (one `npm i -D` line in the template).
