# JSPARK Forge v0.5 (installs once, runs on its own) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After the one `/plugin install` command, JSPARK Forge switches on its own auto-update, ships the code map and
the UI companions, and the doctor reports each piece as on, or off with the one fix (issue #7).

**Architecture:** Three small new modules behind the existing SessionStart `machineMessages` (auto-update switch,
one-time companion install) and one launcher script that Claude Code starts as two plugin MCP servers (code map,
Playwright). The launcher runs pinned npm packages through npx, serves an empty tool list when a server is switched
off, and records what happened in one machine file that the doctor reads. Nothing downloads inside a hook.

**Tech Stack:** Node.js >= 18, no dependencies, `node:test`. Branch `dev/v0.5`.

**Spec:** `docs/design-v0.5.md` (read it first; this plan argues from it).

## Global Constraints

- Hooks never raise and never wait on a download or a child program. Hook time limits in `hooks/hooks.json` stay as they are.
- One automatic switch-on per machine for each piece (auto-update, each companion). Never again after its flag is set.
- `settings.json` is written only when it parses as JSON, only the one key changes, indent and final newline are kept
  (same rules as `scripts/lib/statusline-install.js:37-64`), write is atomic.
- Pins: `codebase-memory-mcp@0.12.1`, `@playwright/mcp@0.0.86`. Marketplace source:
  `{"source":"github","repo":"harishgoswami23/jspark-forge"}`.
- Machine files live in `<CLAUDE_CONFIG_DIR or ~/.claude>/jspark-forge/`: `state.json` (flags, written by hooks),
  `bundled.json` (written by the launcher only), `companions.json` (written by the companion runner only).
- `JSPARK_FORGE_AUTO_SETUP=off` stops the auto-update switch and the companion install (CI, integration tests, the
  doctor's own hook timing run). It is set in `tests/integration/lib.js` and in `doctor.js` `checkHooks` env.
- User-facing text: plain words, short sentences, British spelling, no "simply/just", same voice as existing messages.
- Tests: `npm test` writes to a log; commit only when the log has the exact line `ℹ fail 0`
  (`npm test > "$TEMP/t.log" 2>&1; grep -q "^ℹ fail 0" "$TEMP/t.log" && git commit …`). Never commit on grep of "fail" alone.
- No release, tag, merge to main or push to main. Pushing `dev/v0.5` is allowed.

**`.mcp.json` (exact, subject to F2):**
```json
{
  "mcpServers": {
    "codebase-memory": { "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/scripts/mcp/run.js", "codebase-memory"] },
    "playwright": { "command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/scripts/mcp/run.js", "playwright"] }
  }
}
```

**Launcher behaviour (`run.js <name> [args…]`):**
- Project folder: `CLAUDE_PROJECT_DIR` or the working directory (F2 says which Claude Code provides).
- Server mode (no extra args): `mode` is `run` → spawn `bundled.command(name)` with `stdio: 'inherit'`,
  `windowsHide: true`; record `{ pin, mode, startedAt, exit: null }`; when the child exits with a non-zero code or
  cannot start, record `exit` with `reason` (the error message, or `exit code N`), and exit with the same code.
  Forward SIGTERM/SIGINT to the child.
- Mode `off` or `no-frontend`: record it, then serve an MCP server with no tools on stdin/stdout (newline-delimited
  JSON-RPC 2.0): `initialize` → `{ protocolVersion: <the client's>, capabilities: { tools: {} }, serverInfo: { name: 'jspark-forge-<name>', version: <plugin version> } }`;
  `tools/list` → `{ tools: [] }`; `ping` → `{}`; notifications → no reply; any other request → error `-32601`.
  Exit when stdin closes.
- Pass-through mode (extra args, used by the map refresh): spawn `bundled.command(name, args)` with inherited stdio
  and exit with its code. Not recorded. When mode is `off`, exit 1 with one stderr line "switched off".
- Any internal error: one line on stderr, exit 1. Never writes to stdout except MCP messages.
